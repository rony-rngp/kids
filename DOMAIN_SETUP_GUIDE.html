Custom Domain Setup Guide

Future-proof your MKL Kids Monitor application.

Why use a Custom Domain?

By default, your app uses mkl-monitor.onrender.com. While this works, it ties your app forever to Render. If you ever want to move your server, you would have to update every single phone app manually.

✓ Server Independence
Switch from Render to AWS, Google Cloud, or a Home PC without changing app code.
✓ Professional Branding
ws.yourdomain.com looks much more professional and trustworthy.
✓ Automatic SSL
Modern platforms (like Render/Cloudflare) provide free wss:// security for your domain.
✓ No Migration Pain
Upgrading or downgrading plans won't break your app connections.

Step 1: Purchase a Domain

Buy a domain name from a reputable registrar. Examples: Cloudflare, Namecheap, or GoDaddy.

Pro Tip: Use Cloudflare if possible. It provides the fastest DNS updates and excellent security for free.

Step 2: Add Domain to Render

Action in Render Dashboard:
  1. Open your Web Service (mkl-monitor).
  2. Go to Settings > Custom Domains.
  3. Click Add Custom Domain.
  4. Enter a subdomain (Recommended: ws.yourdomain.com).
  5. Copy the CNAME Target provided (usually mkl-monitor.onrender.com).

Step 3: Update DNS Records

Login to your Domain Registrar (where you bought the domain) and find DNS Management. Add the following record:

Type Name (Host) Value (Target) TTL
CNAME ws mkl-monitor.onrender.com Auto / 1 Hour

Note: It may take 10 minutes to 2 hours for this change to spread across the internet.

Step 4: Update Your Code

Once Render shows the domain status as "Verified", update your code to use the new permanent address.

Android (MonitorService.kt)

// Change this line:
private val REMOTE_SERVER_URL = "wss://ws.yourdomain.com/"

Web Viewer (viewer.html)

// Change this line:
const RELAY_SERVER_URL = "wss://ws.yourdomain.com/";

What happens if I change servers?

If you move your backend to a new service (e.g., AWS):

  1. Deploy your server.js to the new server.
  2. Get the new IP or URL of that server.
  3. Update the DNS CNAME Record (Step 3) to point to the new location.
  4. The App keeps working! Your phones still talk to ws.yourdomain.com, which now points to the new server.
